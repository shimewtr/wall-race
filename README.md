# Wall Race

[GitHub Pages で遊ぶ](https://shimewtr.github.io/wall-race/)

9×9 の盤で、壁を置いて相手の道をふさぎながら、自分のコマを向かい側の端まで先に運ぶ 2 人用ボードゲーム。ブラウザで遊べる。

現在の AI は自己対戦で学習した第11世代（初期の重みに78.0%、第10世代に56.8%）。学習は GitHub Actions で継続している。

人間向けの考え方の手順は [docs/guide.md](docs/guide.md)（自己対戦の分析と、手引きどおりに打つ AI の成績から作っている）。
進め方・現状・次にやること・作業を再開するときのプロンプトは [docs/roadmap.md](docs/roadmap.md)。
AI 学習の経緯・運用手順・別セッションで学習を継続するための文章は [docs/training.md](docs/training.md)。

## 遊び方

```sh
npm install
npm run dev
```

- マスをクリック: コマを動かす（緑のマスが移動先）
- マスの間の溝をクリック: 壁を置く（スマホは 2 回タップで確定）
- `vs AI` は先手・後手を選べ、どちらでも人間側を盤面の手前に表示する
- `対戦` は人間どうし、`観戦` は AI どうし。再生操作は使えない対戦形式では無効になる
- 盤面の上に青・橙それぞれの推定勝率を表示し、決着時は勝者の色と `WIN` を表示する

### ルール

- 自分のコマを、向かい側の端の列まで先に運んだら勝ち
- 手番では「コマを 1 マス動かす」か「壁を 1 枚置く」のどちらか
- 壁は 2 マス分の長さで、1 人 10 枚まで。重ねたり交差させたりはできない
- どちらかのゴールへの道を完全にふさぐ壁は置けない
- 相手のコマが隣にいたら飛び越えられる。後ろが壁や盤の端なら斜めに回り込める
- 300 手で決着しなければ引き分け（自己対戦用の安全装置）

## 構成

| パス | 内容 |
| --- | --- |
| `src/engine/game.ts` | ルールエンジン（DOM 非依存。ブラウザでも Node でも動く） |
| `src/engine/ai.ts` | 探索 AI（αβ 探索 + 反復深化）。評価関数は重みベクトル `Weights` |
| `src/web/` | ブラウザ UI。AI は Web Worker で動く |
| `scripts/arena.ts` | AI 同士を対戦させて勝率を出す |
| `scripts/train.ts` | 自己対戦で評価関数の重みを調整する（SPSA） |
| `training/` | 学習の状態。リポジトリで同期する（下記） |

## 棋譜表記

列 `a`〜`i`（左から）、行 `1`〜`9`（下から）。先手（青）は 1 段目から 9 段目を目指す。

- コマの移動: 移動先のマス（例: `e2`）
- 壁: 壁が接する 2×2 マスの左下のマス + `h`（横）/`v`（縦）（例: `e3h`）

## AI 同士の対戦

```sh
npm run arena -- --games 20 --a '{"maxDepth":3}' --b '{"maxDepth":2,"noise":2}'
```

`--a` / `--b` には `SearchOptions`（`maxDepth`, `timeMs`, `weights`, `noise`）を JSON で渡す。

## 学習

このリポジトリの継続学習は GitHub Actions の Train ワークフローで行う。詳しい運用は [docs/training.md](docs/training.md) を参照。以下は学習スクリプトを直接実行できる環境向けのコマンドで、手元の Mac では重い学習を実行しない。

```sh
npm run train -- --minutes 30            # 30 分回して結果を push
npm run train -- --loop                  # 30 分ごとに push しながら回し続ける
npm run train -- --minutes 5 --no-sync   # git 操作なしで手元だけで試す
```

1. 学習中の重みを少し＋にずらした AI と－にずらした AI を、同じ相手（現チャンピオンか過去の世代）と同じ条件で 64 組ずつ対戦させ、勝率の差の方向へ重みを少し動かす（SPSA）。これを制限時間まで繰り返す
   - 学習・昇格判定は 3 手読み。Web の「つよい」は、同じ重みの 3 手読みに 70.5% 勝つことを確認した 4 手読み（400 局）。学習条件を変えるときは、重みの良し悪しが読みの深さで変わるため、使う深さで鍛えて判定する
   - 序盤 6 手は評価の上位 3 手からランダムに選ぶ（この間だけ 2 手読み。上位を選ぶ間は枝刈りできず重いため）。これが無いと自己対戦の序盤が毎回同じになり、特定の展開にだけ強い重みになる
   - ＋と－を直接戦わせると「すぐ隣の自分にだけ強い」方向へ流れる（じゃんけん型の堂々巡り）ので、相手は固定する
2. 終わったら最新を pull し、自分が進めた分の差分だけを最新の重みに足し込む（Mac と GitHub Actions で同時に回しても進捗が消えない）
3. 現チャンピオン・初期の重みとそれぞれ 400 局対戦し、次をすべて満たせば新しい世代に昇格
   - 対チャンピオンの勝率 55% 以上
   - 対初期の勝率がチャンピオンより 3 ポイント以上下がっていない（特定の相手にだけ強い、を防ぐ）
4. 対チャンピオンの平均勝率が 47% 未満なら、学習中の重みをチャンピオンの重みに戻してやり直す
5. `training/` を commit して push（競合したら 2 からやり直し）

| ファイル | 更新タイミング | 中身 |
| --- | --- | --- |
| `training/state.json` | 毎回 | 学習中の重み・累計の反復回数 |
| `training/history.jsonl` | 毎回 1 行追記 | 実行ごとの記録（場所・回数・重み・チャンピオンへの勝率・昇格したか） |
| `training/champion.json` | 昇格時 | 現チャンピオンの重み |
| `training/champions/gen-NNNN.json` | 昇格時 | 世代ごとのスナップショット |

評価は「1 歩 = 10 点」を単位にしているので、重みはそのまま「何歩分の価値か」と読める。

`wallThreat`（壁 1 枚で相手を遠回りさせられる最大の歩数の差）は、手引き作りで見つけた「壁が残っているうちは歩数のリードがすぐひっくり返る」を評価に入れたもの。1 歩分の重みを足すだけで第 3 世代に 68% 勝った。計算が重いので結果をキャッシュしている。

第10世代からは `wallChain`（壁2枚の連携で、最善の1枚だけより追加で何歩遠回りさせられるか）も評価する。敗戦棋譜をLLMで分類して得た仮説を400局比較し、自己対戦で重みを調整して採用した。

現在は `netWallThreat`（相手を遠回りさせる効果から自分の遠回りを差し引いた、安全な壁の脅威）も調整している。重み5は第11世代に52.9% ±2.4（1,600局）。枝刈りで400局の所要時間を103秒から55秒へ短縮してから採用した。

探索する壁は通常「相手の最短経路をふさぐ壁」に絞っている。コマ周り・自分の経路沿いまで広げた探索との比較は、3 手読みで狭い側 50.5%、4 手読みで 49.1%（各 400 局）と互角だった一方、思考時間はそれぞれ 20→3ms、50→13ms に短縮できた。

GitHub Actions では Train ワークフローが 4 台並列で学習し、終わると次の回を自分で起動する。判定（昇格・リセット）は最後に終わる 1 台だけが行い、他の 3 台は学習した差分を足し込むだけ（`--no-gate`）。止めるときはリポジトリ変数 `TRAIN_CHAIN` を `off` にする。

## 実験

重い比較は Experiment ワークフローで Actions 上で回す（`scripts/experiments/` の `compare` / `guide` / `discover` / `analyze` / `bench` / `profile` などを実行し、結果は実行のサマリーに出る）。

```sh
gh workflow run Experiment -f script=compare -f args="--a '{\"wideRoot\":true}' --b '{\"wideRoot\":false}' --pairs 100"
```
