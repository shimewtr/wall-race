# 進め方と次にやること

このプロジェクトの目的・現状・次にやること・運用上の約束ごとを 1 か所にまとめたもの。
作業を再開するときはまずこのファイルを読む（末尾に再開用のプロンプトがある）。
AI 学習の経緯と詳しい継続手順は [training.md](training.md) にまとめている。

## 目的

1. 自己対戦で強い AI を作る
2. 「どう考えれば強くなれるか」を、人間が実行できる抽象的な手順として文章化する（[guide.md](guide.md)）
   - 手引きの良し悪しは「手引きどおりに打つだけの AI」（手引き AI）の勝率で測る

### 2. AI をさらに強くする

- **新しい特徴量を試す**: 手引き作りで見つかった考え方を AI に入れると強くなった実績がある（`wallThreat`）。候補は次のとおり

  - **自分を苦しくしない壁脅威を採用**: 相手への遠回りから自分への遠回りを引き、最も正味効果の高い壁を選ぶ `netWallThreat` を試した。重み2.5 / 5 / 10は第11世代に51.2% / 55.5% / 44.8%（各400局）。重み5は1600局でも52.9% ±2.4を維持した。全候補で自分の経路を再計算する初版は400局103秒だったが、現在値を超えられない候補を枝刈りして55秒（通常AIは約49秒）まで短縮。重み0の選択手ハッシュ `d639082` も維持したため、初期重み5・`PERTURB=2` で学習対象へ追加した

  - 壁を置く手番コスト: 正味の壁効果から、前進を1手見送るコストを引いたプラス分を `netWallTempo` とした。重み0の選択手ハッシュは基準と同じ `d639082`。重み2.5 / 5 / 10は第11世代に51.0% / 53.0% / 46.3%（各400局）だったが、学習中の `netWallThreat=3.6` に最良の5を足すと45.5% ±4.9（400局）。正味の壁脅威と役割が重なり、同時使用では強くしすぎるため不採用
  - 試し方: 特徴量を追加して重み 0 で入れ、`compare.ts` で「チャンピオン＋その特徴量」対「チャンピオン」を比べる。勝ち越したら学習の対象（`PERTURB`）に入れる

### 3. 手引きを改良する

- **最新世代に勝てない理由を探す**: 手引き AI が最新世代に負けた対局で、チャンピオンと手引き AI の選ぶ手が食い違った局面を集め、手引きに足りない考え方を探す
  - `discover.ts` で盤面・両者の手・探索上の推定損失・勝敗を収集し、LLM で戦術候補を抽出する。候補は手引きなら `guide.ts --opponents league`、AI の特徴量なら `compare.ts` 400 局以上で検証する
  - 第 7 世代との 120 局から「壁の使いすぎ」と「大きな壁脅威への守り」を発見。全世代リーグ各100局で、第 4 版 47.8% → 第 5 版 55.4% を確認して採用した
  - 第 5 版で300局を再分析すると第7世代に56.0%。推定損失上位30局のうち少なくとも17局は自分の壁が残り1枚だった。最後の壁に追加1 / 2 / 4歩のコストを付けると全世代リーグ平均66.5% / 66.8% / 64.4%（第5版55.4%）。追加2歩を第6版として採用した
  - 第 6 版は第8世代との120局で60.0%。敗戦中の有意な判断差341局面には、壁が尽きた後に同じ2マスを往復する例が繰り返しあった。戻る手のコスト0.5歩は全世代リーグを68.4%から71.4%へ改善したため第7版として採用。1歩は平均73.9%だが第8世代への合算が68%から54%へ落ちたため不採用

  - 壁→壁の上位局面には、手引きの縦壁に対して探索AIが横壁で複数の迂回路をまとめて絞る例が繰り返しあった。しかし返し手後の最短ルート本数差を評価する候補0.25 / 0.5は、全世代リーグ各40局で47.2% / 48.3%（現行71.0%）、第9世代3手では13% / 33%（現行65%）に悪化したため不採用。経路本数だけを追うと肝心の距離や壁への耐性を損なう
  - 第9世代との標本を240局へ増やすと手引きは66.3%。壁→壁43局面では、探索AIの壁は即時の正味遠回りが手引きより良い例が0件で平均0.84歩小さい一方、次の壁脅威は18件、経路の柔軟性は21件で改善した。探索AIは即効性より数手先の壁の連携を選んでいる。ただし壁候補間だけで次の壁脅威を追加評価する0.25 / 0.5は全世代リーグ各40局で63.1% / 62.4%（現行71.0%）へ悪化したため不採用。単一指標ではなく壁の応酬を読む必要がある
  - 手引きの再帰読みを2段から3段へ増やす予備測定は、全世代リーグ各10局で64.4%（現行68.9%）。小標本でも改善せず、360局で21分42秒と通常の約7倍/局以上かかったため不採用

- **第11世代での再計測完了**: 自己対戦300局は先手47.0%、平均83.4手、最初の壁は平均17.9手目（相手残り1.7歩）、壁を先に使い切った側35.7%、壁切れ後の歩数判定97.6%。第1〜11世代リーグ各100局は平均69.4%、第11世代2手82%・3手58%。別標本240局では第11世代3手に47.1%
- **第12世代での再計測完了**: 自己対戦300局は先手49.0%、平均83.1手、最初の壁は平均18.1手目（相手残り1.6歩）、壁を先に使い切った側36.1%、壁切れ後の歩数判定93.7%。第1〜12世代リーグ各100局は平均68.6%、第12世代2手73%・3手49%。別標本240局では第12世代3手に43.8%
- **第12世代の判断差**: 敗戦中の有意な判断差534局面は、手引きが壁・探索AIが前進227、前進同士191、壁同士60、手引きが前進・探索AIが壁56。壁同士では探索AIの壁は即時の正味遠回りが平均0.62歩小さい一方、次の壁脅威が26局面で改善し、手引きより0.78歩大きかった。そこで通常評価が最善壁に近い候補から次の壁脅威最大を選ぶ案を試したが、窓0.5 / 1 / 2は全世代リーグ各40局で38.1% / 44.2% / 36.4%（現行69.2%）。将来の壁脅威だけで候補を絞ると即時評価との均衡を壊し、計算も現行の約3倍以上になるため不採用。次は壁の応酬を単一値で置き換えず、既存特徴と重ならない局面条件を探す
- **壁切れ後の往復を抑える第8版を採用**: 前進同士191局面では、手引きが直近マスへ103回戻ったのに対し探索AIは23回。探索AIは154局面でその手の前進量が大きく、平均1.38歩多く縮めた。通常の戻りコスト0.5歩は維持し、自分の壁が0枚のときだけ1 / 2 / 4歩にすると全世代リーグ各40局で69.8% / 70.3% / 68.0%（現行69.2%）。最良の2歩を各100局で確認しても68.7%→69.9%、第12世代2手73%・3手49%を維持したため採用
- **近ゴール時の一律な壁抑制は不採用**: 壁→前進の有意な判断差220局面を分類すると、自分の残り歩数4以下が86局面で推定損失22.3と最も大きかった。一方、壁の即時正味効果は探索AIの前進量より大きい局面が131、同じ70、小さい19で、単純な即時効果不足ではなかった。自分の残り歩数4以下だけ壁へ追加0.5 / 1 / 2歩のコストを付けると、全世代リーグ各40局の平均は38.3% / 26.6% / 18.4%（現行70.3%）。ゴールが近くても必要な壁を広く捨ててしまうため不採用。次は距離だけでなく、壁の後の応酬を含む勝ち筋の有無で分類する
- **壁交換の主導権の単純加算は不採用**: 同じ220局面で両候補への最善応手を比較すると、手引きの壁には相手が178局面で前進し、探索AIの前進には110局面で壁を返した。「自分が壁なら相手が前進、自分が前進なら相手が壁」の交差は72局面（残り4歩以内50）、平均推定損失22.2点だった。ただしこの交換を1 / 2 / 4歩で評価すると全世代リーグ各40局で61.1% / 41.0% / 3.3%（現行70.3%）。両方の応手が同じ局面でそろう場合だけに絞っても、0.5 / 1 / 2歩は39.8% / 47.2% / 35.8%。相手に壁を使わせること自体を目的にすると再帰的な応手判断と即時の歩数差を壊すため不採用。歩数・壁枚数・手番を別々に足すのでなく、探索上の勝敗へつながる具体的な形を探す
- **終盤の1歩を一律に重くする案は不採用**: 第12世代の `urgency` は約6.76歩分まで学習されているため、手引きの応手後評価にも `1/(自分の残り歩数+1) - 1/(相手の残り歩数+1)` を2 / 4 / 8倍して加えた。全世代リーグ各40局の平均は61.0% / 66.1% / 64.0%（現行70.3%）。倍率4は第10〜12世代の3手読みに60% / 68% / 63%（現行40% / 57% / 50%）と改善したが、過去世代で崩れるため不採用。AIで有効な非線形特徴も、他の学習済み特徴との組み合わせを切り離して手引きへ移すと一般化しない
- **序盤限定の壁温存は不採用**: 第11世代との敗戦中の有意な判断差483局面は、手引きが壁・探索AIが前進208、逆58、壁同士58、前進同士159。自分の壁が10枚の21局面はすべて壁→前進だったため、「まだ一枚も壁がない間だけ最初の壁を待ち、誰かが置いた後は通常判断へ戻す」候補を試した。距離2 / 3 / 4は全世代リーグ各40局でいずれも68.4%（現行70.2%）。第10・11世代3手には43→53%、60→70%と改善したが過去世代で崩れ、特定世代への合わせ込みになるため不採用
- **壁2枚の連携の単純加算は不採用**: 第11世代への昇格に効いた `wallChain` と同じく、相手の返し後に「壁2枚で作れる総迂回 − 最善の1枚の迂回」の差を形勢へ足した。全世代リーグ各40局で倍率0.125 / 0.25 / 0.5は66.8% / 61.4% / 44.7%（現行70.2%）。強く足すほど悪化したため、AIには有効でも人間向け手順への単純加算は不採用
- **まだ分かっていないこと**（guide.md 末尾）: 守りの壁の使いどころ、「相手の一番いやな返し」や「壁 1 枚で遠回りさせられる歩数」を盤面で素早く見つけるコツ
- **読みやすくする**: 盤面の図や具体例を入れる。Web から手引きを読めるようにする

### 4. Web

- 形勢の勝率換算は、30〜60% のあたりの当てはまりが粗い。対局数を増やす、局面の進み具合で式を分けるなどで改善できる
- 手引きの手順で選んだ手を「ヒント」として表示する機能（手引きを実戦で練習できる）

## 運用上の約束ごと

- **手元の Mac では学習・対戦ベンチなどの重い処理を回さない。** 重い処理は GitHub Actions で回す
  - 学習: Train ワークフロー（連鎖実行。止めるときは `gh variable set TRAIN_CHAIN --body off`）
  - 実験: Experiment ワークフロー。`gh workflow run Experiment -f script=<scripts/experiments のファイル名> -f args="..."`。結果はログとサマリーに出る
  - 手元では数秒で終わる `npm test` / `npm run build` だけ
  - Web の見た目の確認は、push して GitHub Pages に反映されたものをブラウザで見る（キャッシュを避けるため URL に `?v=<コミット>` を付ける）
- **数字で確かめてから変える。** 探索の高速化は `bench.ts` の「選んだ手のハッシュ」が変わらないことを確かめる。AI の変更は `compare.ts`（400 局以上）、手引きの変更は `guide.ts --opponents league` で比べる
- **特定の相手に合わせない。** 手引きは全世代の平均で、AI の昇格は対チャンピオンと対初期の重みの両方で判定する
- **展開をばらけさせる。** 自己対戦の序盤 6 手は上位 3 手からランダム。これが無かったころの統計は同じ展開の繰り返しで偏っていた
- コミットの作者は GitHub の noreply アドレス（公開リポジトリに会社のメールを出さない）。ゲームの元になった商品の名前は使わない
- 返答・ドキュメントは日本語
