このプロジェクトの目的・現状・次にやること・運用上の約束ごとを 1 か所にまとめたもの。
作業を再開するときはまずこのファイルを読む（末尾に再開用のプロンプトがある）。

## 目的

1. 自己対戦で強い AI を作る
2. 「どう考えれば強くなれるか」を、人間が実行できる抽象的な手順として文章化する（[guide.md](guide.md)）
   - 手引きの良し悪しは「手引きどおりに打つだけの AI」（手引き AI）の勝率で測る

### 2. AI をさらに強くする

- **分析手法を広げる**: [analysis.md](analysis.md) に、反実仮想、近傍境界、対称性、読み深さ差、手順モチーフ、概念クラスタ、決定木蒸留、特徴量アブレーション、評価校正、世代間非推移性、苦手局面からの重点学習を整理した。まず低コストで誤分析を減らせる `symmetry.ts`、`horizon.ts`、`ablation.ts` の順に進める
  - `symmetry.ts` を実装し、第12世代の120局面を検査した。`wallChain` が同率候補を走査順で選ぶため評価値が左右9件・上下4件で非対称になることを発見。盤面を正規化して候補を選ぶ修正後は評価値240比較が全一致し、旧方式との400局は49.5% ±4.9で互角。4手読みは27.8→31.9ms/手で、正しさの修正として採用した
  - `horizon.ts` を実装し、第12世代の120局面を1〜4手読みで比較した。3→4手で最善手が変わるのは14局面（11.7%）で、前進→壁6件に対し壁→前進2件。変更率は中盤17.9%が最大で、壁が双方約6枚残る応酬に深読みが効く。3→4手の平均ノードは219→690（約3.1倍）。次は `ablation.ts` で、深さ依存局面を含めて既存特徴量の寄与と重複を測る
  - `ablation.ts` を実装し、第12世代の120局面で全13特徴量を1つずつ無効化した。判断変更率は `urgency` 36.7%、`wallDiff` 35.0%、`pathDiff` 25.8%が上位。`netWallThreat` の変更8局面は全て `wallThreat` と重なり、`adjacent` は0局面、`myWalls` は評価差が大きいのに手は4局面しか変えなかった。次は `netWallThreat`、`wallChain`、`myWalls`、`adjacent` を各400局で無効化比較する
    - 無効化比較では `wallChain` あり57.3%（400局）、`netWallThreat` あり55.8%（別シード合計800局）で、重複があっても両方に独立した勝敗上の価値があった。`adjacent` は50.0%（400局）で現世代では休眠しているが、計算が軽く学習で再利用できるため維持する
    - `myWalls` ありは別シード合計800局で50.0%。評価値を大きくずらす一方で強さへ寄与しないため、評価・学習対象から外した。既存の学習JSONにキーが残っていても読み込み時に無視できる。除外後6判定は50.2% / 51.5% / 51.8% / 50.5% / 51.9% / 49.8%でリセットなく、学習連鎖も正常に継続している
    - 無効化後の horizon 再測定では3→4手の最善手変更は14/120のまま、厳密な偶奇振動は3→1局面、生評価の符号反転は40.0%→29.2%に減った
    - `motifs.ts` を実装し、独立シード各600局面で3→4手の変更率は13.2% / 11.0%、中盤は18.8% / 22.8%だった。深読みで前進から有利な横壁へ変わる型が16 / 17件で最多。その後の `P+ P+ H+`（双方が前進してから有利な横壁）は変更群で安定群の13.84倍 / 7.88倍現れた。次は `boundaries.ts` で既存壁を1枚ずつ除き、「今進むか、今横壁を置くか」を分ける盤面条件を特定する
    - `boundaries.ts` で壁の形状と残数の効果を分離した。独立標本の変更局面26 / 31件のうち、形状だけの編集で不一致が消えたのは21 / 24件、残数だけでは7 / 10件。連結壁率と、除去時の最短距離変化は不一致を解消する壁で両標本とも高かったが、横壁率の差は再現しなかった。次は `distill.ts` で「経路が少数の既存壁に依存する脆さ」を含む小さな判定木を未知シード評価する
    - `distill.ts` を独立シード各800局面で評価した。最大4段の基本量だけの木は未知シードAUC 0.681、経路脆弱性込みは0.664で悪化。危険度上位30%だけ4手読みしても判断差の51.4%しか拾えず、適応的な深さ切替には不採用。次は実際の深さ依存局面をアーカイブし、通常学習とは独立に一部の自己対戦をそこから始める実験を準備する
    - `archive.ts` で固定シード1,200局面から判断差108局面を復元可能なJSONへ保存した。序盤31・中盤42・終盤35、前進→壁59件で、結果はrun `40101967637` のartifactに保存済み
    - `archive-training.ts` で開始局面0% / 10% / 20%を各8反復×32組で予備比較した。対チャンピオンの通常局面は51.7% / 49.5% / 49.0%、アーカイブ局面は全て50.0%。10%・20%候補を0%候補と直接比べても通常・アーカイブとも50.0%で、短期学習では方策差が生じなかった。改善根拠がないため400局への拡大やTrain本体への接続はしない
    - `generation-league.ts` で第1〜12世代を各組100局、合計6,600局で総当たりさせた。第12世代は全過去世代に勝ち越して平均63.9%で首位。初回の第4→第5→第9→第4という循環候補は、別シード各組400局では第9>第5>第4の一方向になり再現しなかった。学習相手の配分は変えず、次は評価値の校正誤差を局面条件別に分析する
    - `calibrate.ts` を独立800局で検証した。高信頼で外した局面は全体2.6%だが、終盤6.1%、盤上の残り壁14〜20枚で5.5%に集中した。残り壁×ゴールの近さを不確実性として加えた式は、別seedの独立検証で全局面のBrier scoreを0.1636→0.1548、高不確実性局面を0.2688→0.2298へ改善したため、評価関数は変えずWebの勝率表示へ採用した
    - `confidence-errors.ts` で高信頼誤予測を対局ごと・盤面ごとに重複除外し、同条件の正解局面と比較した。独立1,600局では誤予測群の3→4手変更率15.8%、対照9.2%。ただし判断差19局面の反実仮想は3手59.7%・4手64.2%（+4.5pt）、局面単位では改善9・悪化7・同じ3で、初回の+7.0ptを安定再現しなかった。適応的4手読みにはまだ使わない
    - 誤予測では優勢評価側の壁不足が対照より多かったため校正項を独立31,632局面で試したが、全体Brier scoreは0.1675→0.1666だけで、2枚以上不足時のlog lossは0.4485→0.4501へ悪化した。Web・評価特徴とも不採用
    - `value-model.ts` で既存特徴量と文脈交互作用の小さな価値モデルをゲーム単位で学習/評価分割した。別seed 2回で現行校正→交互作用モデルのBrier scoreは0.1619→0.1602 / 0.1636→0.1590、log lossは0.4740→0.4712 / 0.4760→0.4664と改善したが、高信頼誤りは悪化した。「壁が減るほど距離差を重くする」特徴は重み5 / 2の各400局で47.3% / 47.5%。`壁差×|歩数差|` は初回400局53.4%だったが独立1,200局48.0%、合計49.4%で再現しなかった。予測改善は方策改善を意味しないため、どちらもAI評価・Web校正へ入れない

- **新しい特徴量を試す**: 手引き作りで見つかった考え方を AI に入れると強くなった実績がある（`wallThreat`）。候補は次のとおり
  - 最短ルートの本数: `routeDiversity=5` が当時のチャンピオンに **58.5% ±4.8**（400 局）。計算結果をキャッシュして、選択手ハッシュを変えずに 20.1 → 15.9ms/手まで高速化し、`PERTURB=2` で学習対象に追加した。第8世代では2.577、第9世代への昇格時には0.041まで学習で下がったため、現在のリセットは第9世代の値を基準にする
  - 最短ルートが分岐するまでの歩数: 第12世代の探索AIが即時効果より将来の壁脅威を作る傾向から、最短路が一本道のまま続く歩数差を `routeCommitment` として試した。重み0の選択手ハッシュはmainと同じ `9f51272e`。重み0.5 / 1 / 2は第12世代に49.0% / 48.5% / 37.5%（各400局）で、強くするほど悪化し、非ゼロ時の思考も概ね2〜4倍になった。分岐位置だけを追うと距離や壁の具体的な効き方を損なうため不採用
  - 壁2枚の連携: 敗戦ログから、探索AIは即時の遠回りを0.84歩犠牲にして次の壁脅威を作る傾向を発見。2枚で作れる総迂回のうち1枚だけでは得られない追加分を `wallChain` とした。重み2は第9世代に **56.3% ±4.9**（400局）だが平均19ms/手だった。1枚目を即時効果最大の1候補だけに絞っても **55.0% ±4.9**（400局）を保ち、平均9ms/手まで短縮。重み0のベンチは第9世代基準ハッシュ `34ff33e7` を維持したため、初期重み2・`PERTURB=1` で学習対象に追加。2サイクル後に重み1.845で第10世代へ昇格した。さらに最善壁と2枚目の計算を通常キャッシュで共有し、第10世代の選択手ハッシュ `c2f01fde` を維持したまま14.3→6.6ms/手、1.61→3.56組/秒へ高速化した
    - Trainの実測は第1段階490反復、完全版の最初は483反復だったが、キャッシュ改善後は692 / 705反復。さらに最短経路計算の直接展開・作業配列再利用後、第11世代の昇格サイクルは1,276反復、その後は1,189 / 1,241 / 1,131 / 1,344反復まで増えた（ランナー差あり）
    - プロファイルでは `shortestDistance` が自己時間62.5%。壁配置ごとの全81マス距離表をキャッシュする案はハッシュ `c2f01fde` を維持したが、当たり率53.4%で6.6→16.7ms/手、3.56→1.41組/秒へ悪化。全マスBFSとキー作成が早期終了BFSより高くつくため不採用
    - 早期終了BFSのまま訪問配列の初期化を世代番号に替える案も、同時刻のActions比較で従来11.0ms/手・1.76組/秒・プロファイル942msに対し、11.0ms/手・1.59組/秒・993ms。ハッシュ `c2f01fde` は一致したが改善せず不採用
    - `shortestDistance` の上下左右の壁判定を9×9固定盤向けに直接展開した版は、同時刻のActions比較で10.8→7.0ms/手、1.40→3.11組/秒。プロファイル総時間は596→594msと同等だが同関数の自己時間比率は65.2%→41.9%へ低下し、ハッシュ `c2f01fde` も一致したため採用
    - 続けて `shortestPath` も探索順を保ったまま壁判定を直接展開し、作業配列を再利用。同時刻比較で6.8→6.1ms/手、2.62→2.89組/秒、プロファイル656→278ms、同関数の自己時間10.0%→5.8%。ハッシュ `c2f01fde` 一致で採用
  - 4 歩以上の壁脅威: 手引きで有効だった閾値を `severeWallThreat` として試したが、重み 2.5 / 5 / 10 はチャンピオンに 43.0% / 41.3% / 35.8%（各400局）で全敗。探索の評価値には採用しなかった
  - 壁1枚で歩数負けを先着可能へ変えられるか: 敗戦分析で「目前の負けを止めても勝ち筋が残らない壁」が多かったため、自分への副作用も含む正味迂回で歩数勝負の境界を跨げる場合だけを `wallRescue` とした。重み0の選択手ハッシュはmainと同じ `9f51272e`、速度も7.7ms/手対7.8ms/手。重み2.5 / 5 / 10は第12世代に46.8% / 43.3% / 41.5%（各400局）で、強くするほど悪化した。1枚で一時的に歩数を逆転できること自体が、最終的な勝ち筋を表さないため不採用
  - 守りの壁: 広い候補の勝率は狭い候補に対して3手読み49.5%、4手読み50.9%（各400局）で互角。狭い候補は3手20→3ms、4手50→13msに短縮できたため既定値に採用。第7世代300局で守りの壁は全壁の6.4%だった

- **応手後の先着可能性で緊急防御を再分析**: 前進→壁56局面のうち、探索AIの壁を選んでも相手の最善応手後に両案とも歩数で後手なのが39局面。上の緊急防御条件22局面も20局面は両案とも後手で、壁側だけ先着可能なのは2局面だった。上位の大差例の多くは探索AIも負けを延ばしているだけで、手引きの勝率を変えないため、敗戦ログの推定損失だけで候補化しない
- **歩数不利時の弱い壁抑制も不採用**: 壁→壁60局面を勝利29局面と対照すると、手引きの正味効果1歩以下の壁は敗戦50.0%・勝利13.8%。「弱い壁 × 歩数で負け・同点」まで絞ると敗戦21・勝利1局面だったため、この場合だけ追加0.25 / 0.5 / 1歩を課した。全世代リーグ各40局は68.0% / 68.4% / 66.4%（現行70.3%）。第12世代3手読みは73% / 80% / 57%（現行50%）だが過去世代で崩れ、最新世代への合わせ込みになるため不採用
- **候補手ごとの終局追跡を導入**: 推定損失が大きくても両方の手で負ける局面を除くため、`counterfactual.ts` で手引き手と探索AI手をそれぞれ強制し、その後を同じ探索AI同士で終局まで指すようにした。120局から選んだ上位30局面では探索AI手で勝敗改善9・同じ18・悪化3。240局の壁→壁46局面に絞ると改善11・同じ34・悪化1だった。改善群は自分の残り歩数4.45、相手6.64、探索AI壁による次の壁脅威差+3.36が平均で、非改善群の7.29 / 4.29 / -0.26と明確に違った。「自分が残り5歩以内 × 先着可能 × 次の壁脅威が2歩以上良い」は改善7・非改善1まで絞れたが、その条件で脅威最大の壁へ置き換える候補は全世代リーグ各40局で閾値1 / 2 / 3が49.2% / 50.8% / 60.0%（現行70.3%）。良かったのは探索AIが選んだ具体的な連携手であり、脅威最大化には一般化できないため不採用
- **連結壁は説明力があるが特徴量化は不採用**: 上の改善7局面は探索AI手のあと平均3.14手で次の自分の壁を置き、非改善1局面は16手後だった。改善7局面中5局面は同方向の壁をアンカー2マス離して端へつなぎ、長い障壁を作った。壁→壁の改善11局面全体でも、端につなぐ2枚目の正味効果は探索AI壁3.73・非改善35局面0.60だった。4手読みで終局追跡しても改善11・非改善35、連結効果3.82 / 0.57と全体傾向は再現したが、狭い複合条件の内訳は改善7・非改善1から5・3へ弱まり、個別判定は読みの深さに依存した。そこで「残り5歩以内かつ先着可能」で全ての1枚目候補と連結2枚目を調べる `wallExtension` を試した。重み0は選択手ハッシュ `9f51272e` でmainと一致したが、重み1.25 / 2.5 / 5は第12世代に51.5% / 49.8% / 47.8%（各400局）で、平均思考時間も通常1〜2msから8〜9msへ増えた。小さい重みも追加確認基準52.5%に届かず、既存の `wallChain` と役割が重なる重い特徴量なので不採用。次は盤面全体の静的特徴を増やさず、探索内で2枚連携の1枚目候補を安く残せるかを調べる
- **序盤限定の壁温存は不採用**: 第11世代との敗戦中の有意な判断差483局面は、手引きが壁・探索AIが前進208、逆58、壁同士58、前進同士159。自分の壁が10枚の21局面はすべて壁→前進だったため、「まだ一枚も壁がない間だけ最初の壁を待ち、誰かが置いた後は通常判断へ戻す」候補を試した。距離2 / 3 / 4は全世代リーグ各40局でいずれも68.4%（現行70.2%）。第10・11世代3手には43→53%、60→70%と改善したが過去世代で崩れ、特定世代への合わせ込みになるため不採用
- **壁2枚の連携の単純加算は不採用**: 第11世代への昇格に効いた `wallChain` と同じく、相手の返し後に「壁2枚で作れる総迂回 − 最善の1枚の迂回」の差を形勢へ足した。全世代リーグ各40局で倍率0.125 / 0.25 / 0.5は66.8% / 61.4% / 44.7%（現行70.2%）。強く足すほど悪化したため、AIには有効でも人間向け手順への単純加算は不採用
- **まだ分かっていないこと**（guide.md 末尾）: 守りの壁の使いどころ、「相手の一番いやな返し」や「壁 1 枚で遠回りさせられる歩数」を盤面で素早く見つけるコツ
- **読みやすくする**: 盤面の図や具体例を入れる。Web から手引きを読めるようにする

### 4. Web

- 形勢の勝率換算は、30〜60% のあたりの当てはまりが粗い。対局数を増やす、局面の進み具合で式を分けるなどで改善できる
- 手引きの手順で選んだ手を「ヒント」として表示する機能（手引きを実戦で練習できる）

## 運用上の約束ごと

- **手元の Mac では学習・対戦ベンチなどの重い処理を回さない。** 重い処理は GitHub Actions で回す
  - 学習: Train ワークフロー（連鎖実行。止めるときは `gh variable set TRAIN_CHAIN --body off`）
  - 実験: Experiment ワークフロー。`gh workflow run Experiment -f script=<scripts/experiments のファイル名> -f args="..."`。結果はログとサマリーに出る
  - 手元では数秒で終わる `npm test` / `npm run build` だけ
  - Web の見た目の確認は、push して GitHub Pages に反映されたものをブラウザで見る（キャッシュを避けるため URL に `?v=<コミット>` を付ける）
- **数字で確かめてから変える。** 探索の高速化は `bench.ts` の「選んだ手のハッシュ」が変わらないことを確かめる。AI の変更は `compare.ts`（400 局以上）、手引きの変更は `guide.ts --opponents league` で比べる
- **特定の相手に合わせない。** 手引きは全世代の平均で、AI の昇格は対チャンピオンと対初期の重みの両方で判定する
- **展開をばらけさせる。** 自己対戦の序盤 6 手は上位 3 手からランダム。これが無かったころの統計は同じ展開の繰り返しで偏っていた
- コミットの作者は GitHub の noreply アドレス（公開リポジトリに会社のメールを出さない）。ゲームの元になった商品の名前は使わない
- 返答・ドキュメントは日本語
